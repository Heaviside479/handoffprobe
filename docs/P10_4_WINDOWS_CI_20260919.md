# P10.4 Windows CI coverage

Date: 2026-09-19

Status: **COMPLETE — GitHub-hosted Windows validation passed 2026-09-19**

## Purpose

Determine whether the current HandoffProbe repository quality and package gates
run successfully on a GitHub-hosted native Windows environment.

The existing compatibility baseline intentionally does not claim Windows
support. This candidate adds a real verification path before any such claim is
changed.

## Verified CI matrix

- `ubuntu-latest`
- `macos-latest`
- `windows-latest`
- Node.js `24`
- `npm ci`
- `npm run check`
- `npm run package:check`

The same repository quality and package gates must execute on all three
operating systems.

`fail-fast` remains disabled so a Windows-specific failure stays observable
without hiding Linux or macOS results.

## Pre-admission review

The repository-level Quality workflow uses portable npm commands and does not
force a Unix shell.

The reusable HandoffProbe GitHub Action is a separate compatibility surface and
currently contains explicit `shell: bash` steps. This Windows CI candidate does
not by itself claim native Windows compatibility for that reusable Action.

The package build uses a Node-based `rmSync` cleanup followed by TypeScript
compilation. The npm script uses `&&`, which is handled by npm's platform shell,
but the real GitHub-hosted Windows run remains the authority for admission.

## First GitHub-hosted candidate result

The first Windows candidate run exposed a repository checkout-normalization
issue before runtime, type or security validation was reached.

Evidence:

- PR: `#142`;
- workflow run: `35463265731`;
- job: `Quality (windows-latest)`;
- GitHub-hosted environment: Windows Server 2025;
- Node.js: `24.20.0`;
- npm: `11.19.0`;
- checkout: success;
- Node setup: success;
- `npm ci`: success;
- `npm run check`: failed during `format:check`;
- package validation: skipped because the quality gate stopped first.

Prettier reported 219 repository files as formatting mismatches immediately
after the Windows checkout. The repository previously had no `.gitattributes`
or `.editorconfig` line-ending policy. The failure is classified as a
checkout/EOL normalization issue rather than 219 independent source defects.

Remediation candidate: repository text checkouts are pinned to LF through
`.gitattributes` using `* text=auto eol=lf`.

Windows admission remains pending until a new GitHub-hosted Windows run passes
the complete quality and package-validation path.

## Admission result

The P10.4 Windows admission rule is satisfied.

GitHub-hosted `windows-latest` completed the same Node 24 quality and package
validation path as Linux and macOS after the repository line-ending policy was
made explicit.

The native Windows compatibility exclusion for the reusable composite GitHub
Action remains documented separately because that Action still uses
`shell: bash`.

## Product effect
