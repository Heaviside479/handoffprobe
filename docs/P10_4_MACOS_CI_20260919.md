# P10.4 macOS CI coverage

Date: 2026-09-19

Status: **ACTIVE — GitHub-hosted macOS validation pending**

## Purpose

Add an explicit GitHub-hosted macOS verification path alongside the existing Linux CI path.

## Candidate CI matrix

- `ubuntu-latest`
- `macos-latest`
- Node.js `24`
- `npm ci`
- `npm run check`
- `npm run package:check`

The same repository quality and package gates must pass on both operating systems.

`fail-fast` is disabled so a failure on one platform remains visible even when another platform succeeds.

## Admission rule

The P10.4 macOS roadmap item remains open until the GitHub-hosted `macos-latest` pull-request job completes successfully.

Local macOS validation alone is not used to close this CI-specific roadmap item.

## Local pre-PR hardening

The first full local quality run exposed two test-infrastructure assumptions:

- the Cleanup E verification still expected a literal `runs-on: ubuntu-latest` line even though Linux remains present through the new OS matrix;
- the existing simultaneous full-corpus concurrency test exceeded Vitest's default 5-second per-test timeout under full-suite load.

The Linux verification now checks the matrix membership plus matrix runner binding.

Only the long-running simultaneous full-corpus concurrency regression receives an explicit 15-second test timeout. This changes no security semantics and is not a performance or release threshold.

## Product effect

This change adds verification coverage only.

It changes no stable attack ID, CLI contract, report schema, config schema, protocol baseline or package version.
