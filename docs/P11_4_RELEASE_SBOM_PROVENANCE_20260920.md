# P11.4 release SBOM and provenance boundary

Date: 2026-09-20

Status: **IMPLEMENTATION CANDIDATE — protected workflow evidence pending**

## Purpose

Add a runtime-focused Software Bill of Materials gate to the Release Candidate
path and define the exact provenance boundary for future npm publication.

P11.4 does not publish a package and does not claim publication provenance for
an unpublished Release Candidate artifact.

## Raw npm nondeterminism

Two immediately repeated raw SPDX outputs were not byte-identical.

The observed top-level differences were limited to:

- `creationInfo`;
- `documentNamespace`.

This is release-document metadata rather than an observed difference in the
runtime dependency graph.

## Deterministic dependency comparison

P11.4 preserves the actual npm-generated SPDX document metadata.

It does not rewrite:

- `creationInfo.created`;
- `documentNamespace`.

Those fields remain part of the real SPDX document generated by npm.

For deterministic comparison only, HandoffProbe derives a separate projection
from each generated document.

The comparison projection removes exactly:

- `creationInfo.created`;
- `documentNamespace`.

It then emits JSON object keys in stable sorted order.

The comparison projection is not distributed as an SPDX document and no SPDX
conformance claim is made for it.

The workflow generates two real SPDX SBOMs independently and requires the two
comparison projections to be byte-identical.

The local corrected implementation produced:

- real SPDX documents: not byte-identical;
- deterministic comparison projections: byte-identical;
- comparison fingerprint A:
  `193579b50cb547a3a80c7bed3a0f0c4d2f786d6771c8b2e5048d23ffd885998e`;
- comparison fingerprint B:
  `193579b50cb547a3a80c7bed3a0f0c4d2f786d6771c8b2e5048d23ffd885998e`.

This demonstrates stable observed package/dependency content while preserving
the document-creation semantics of the actual SPDX output.

## Release toolchain

The Release Candidate workflow pins npm `11.19.1`.

This matches the npm version already pinned by the stage-only publication
workflow and removes an unnecessary release-engineering toolchain difference
between candidate validation and future staging.

This does not claim byte identity across future npm versions.

## SBOM retention

For protected pull-request validation, the workflow generates and validates
the SBOM but does not retain it as an uploaded artifact.

For a manually dispatched Release Candidate run from merged `main`, the first
real npm-generated SPDX document is retained as a GitHub Actions artifact for
seven days. The upload step requires both `workflow_dispatch` and
`refs/heads/main`.

The deterministic comparison projection is validation material only and is
not uploaded as an SPDX artifact.

## Provenance boundary

The existing stage-only publication workflow uses npm Trusted Publishing with
GitHub OIDC.

For a future public package published through that trusted relationship, npm
provides publication provenance through the real trusted-publishing path.

P11.4 does not manufacture an equivalent claim for an unpublished candidate.

No package is staged or published by P11.4.

P11.4 also does not create a GitHub artifact attestation for temporary
pull-request or Release Candidate artifacts.

The first real public package after `0.4.0` must separately verify the registry
provenance produced by the actual publication path.

## Release boundary

P11.4 does not:

- change `handoffprobe@0.4.0`;
- stage an npm package;
- publish an npm package;
- approve a staged npm package;
- create or move a Git tag;
- create a GitHub Release;
- change runtime source;
- change the stable 23-attack corpus;
- add a runtime or development dependency.

## Completion gate

P11.4 is complete only after:

- the implementation passes protected pull-request validation;
- the Release Candidate job demonstrates real SPDX generation and a
  deterministic dependency fingerprint on that protected pull request;
- the implementation is merged normally;
- the Release Candidate workflow succeeds from merged `main`;
- the merged-main run records the real release-SBOM SHA-256 and one
  deterministic dependency-fingerprint SHA-256 from two byte-identical
  comparison projections;
- the merged-main run retains the real release SBOM as a short-lived workflow
  artifact;
- no package is staged or published merely to validate P11.4.

Live npm publication provenance remains evidence for the first separately
admitted future release rather than a reason to publish a version during this
phase.
